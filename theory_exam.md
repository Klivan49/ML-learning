## 1. Постановка задачи

**Что делает проект?** Принимает на вход файл (или папку с файлами) и автоматически раскладывает их по категориям: документы, картинки, архивы, код, медиа, прочее.

**Формальная постановка:**
- Вход: файл → извлекаем вектор признаков **x ∈ ℝ⁴⁸**
- Выход: метка класса **y ∈ {documents, images, archives, code, media, other}**
- Это задача **обучения с учителем (supervised learning)**, а именно — **многоклассовая классификация (multiclass classification)**

**Почему именно ML, а не правила?** Потому что нельзя жёстко прописать правила для всех случаев. Файл `report_2024.pdf` — это документ. Но `screenshot_2024.png` — это изображение. А `main.py` — это код. ML сам находит неявные зависимости между признаками.

## 2. Типы машинного обучения

В проекте используется **обучение с учителем**. Всего в ML выделяют три парадигмы:

### Обучение с учителем (Supervised Learning)
- Есть датасет `(X, y)`, где `X` — признаки, `y` — истинные метки
- Задача: найти функцию `f: X → y`
- **Регрессия:** `y` — непрерывное число (предсказание цены)
- **Классификация:** `y` — дискретная метка (наш случай)

### Обучение без учителя (Unsupervised Learning)
- Есть только `X`, меток `y` нет
- Задача: найти скрытую структуру в данных
- Примеры: кластеризация (K-means), снижение размерности (PCA)
- В проекте не используется, но можно добавить: например, кластеризовать расширения по похожести

### Обучение с подкреплением (Reinforcement Learning)
- Агент взаимодействует со средой, получает награду/штраф
- Цель: максимизировать суммарную награду
- Пример: игры, робототехника

### 3.2. Size features (`features.py:37-63`)

**Код:**
```python
def extract_size_features(size_bytes: int) -> Dict[str, float]:
    log_size = math.log1p(size_bytes)  # ln(1 + size)
    kb = size_bytes / 1024
    mb = size_bytes / (1024 * 1024)
```

**Зачем `log1p`?** Размеры файлов распределены неравномерно: от 10 байт (пустой .txt) до 10 ГБ (видео). Если подать в модель сырые значения, то большие числа будут доминировать, а градиентный спуск будет нестабильным. `log1p` сжимает диапазон:
- 10 байт → ln(11) ≈ 2.4
- 1 КБ → ln(1025) ≈ 6.9
- 1 МБ → ln(1_048_577) ≈ 13.9
- 1 ГБ → ln(1_073_741_825) ≈ 20.8

**Пример:** файл `data.zip` размером 1_500_000 байт (~1.5 МБ)
- `size_bytes = 1_500_000`
- `log_size = ln(1_500_001) ≈ 14.2`
- `size_kb = 1464.8`
- `size_mb = 1.43`
- `size_medium = 1.0` (попадает в диапазон 100 КБ — 10 МБ)

### 3.4. Content features — энтропия Шеннона (`features.py:86-92`)

**Самая математически насыщенная часть.** Считаем энтропию байт файла — меру «случайности» данных.

**Формула энтропии Шеннона:**
```
H(X) = - Σ p(x) · log₂(p(x))
```

где `p(x)` — частота байта со значением x (0..255) в файле.

**Код:**
```python
def compute_byte_entropy(content: bytes) -> float:
    counts = np.bincount(np.frombuffer(content, dtype=np.uint8), minlength=256)
    probs = counts / counts.sum()
    ent = -np.sum(p * np.log2(p) for p in probs if p > 0)
    return float(ent)
```

**Примеры значений:**
- Текстовый файл: большинство байт — буквы ASCII (65-122), энтропия ≈ 4.0-4.5
- Сжатый .zip: байты распределены почти равномерно, энтропия ≈ 7.5-7.9
- Пустой файл: энтропия = 0 (все байты одинаковые, нет неопределённости)
- Исполняемый .exe: энтропия ≈ 6.0-7.0

**Интуиция:** Энтропия — это количество бит информации на один байт. Если все байты одинаковые (например, 100 нулей) — энтропия 0, никакой информации. Если байты распределены равномерно (256 значений с равной вероятностью) — энтропия 8 бит (максимум).

## 4. Модели и их математика

### 4.1. Логистическая регрессия (LogisticRegression)

#### Интуиция
Название обманчивое — это не регрессия, а **линейная модель классификации**. Она проводит прямую (гиперплоскость) между классами.

#### Математика для бинарного случая
Логистическая регрессия предсказывает вероятность того, что объект принадлежит классу 1:

```
P(y = 1 | x) = σ(w·x + b) = 1 / (1 + e^{-(w·x + b)})
```

Где:
- **x** — вектор признаков (в нашем случае 48 чисел)
- **w** — вектор весов (какой признак насколько важен)
- **b** — bias (смещение)
- **σ(z)** — сигмоидная функция

**Форма сигмоиды:** S-образная кривая. При любом **z** на входе, на выходе число от 0 до 1 — то есть вероятность.

```
σ(z) = 1 / (1 + e^{-z})
```

![Сигмоида: z → -∞ ⇒ σ → 0; z → +∞ ⇒ σ → 1; z = 0 ⇒ σ = 0.5]

#### Математика для многоклассового случая (наш проект)

Обобщение сигмоиды на K классов — **softmax**:

```
P(y = k | x) = exp(w_k · x + b_k) / Σⱼ exp(w_j · x + b_j)
```

Для каждого класса k считается свой "вес" w_k·x + b_k. Softmax превращает K произвольных чисел в вероятности (сумма = 1).

**Пример:** три класса (documents, images, code). Считаем линейные комбинации:
- documents: w₁·x + b₁ = 2.5
- images: w₂·x + b₂ = 0.3
- code: w₃·x + b₃ = 1.1

Numerator для documents = exp(2.5) = 12.18
Numerator для images = exp(0.3) = 1.35
Numerator для code = exp(1.1) = 3.00

Sum = 12.18 + 1.35 + 3.00 = 16.53

P(documents) = 12.18/16.53 = 0.74
P(images) = 1.35/16.53 = 0.08
P(code) = 3.00/16.53 = 0.18

**Ответ: documents с вероятностью 74%.**

#### Функция потерь: Cross-Entropy (LogLoss)

Модель обучается, минимизируя **кросс-энтропию**:

```
L = - (1/N) · Σᵢ Σₖ yᵢₖ · log(pᵢₖ)
```

Где:
- N — число объектов
- yᵢₖ — 1, если объект i принадлежит классу k, иначе 0 (one-hot encoding)
- pᵢₖ — предсказанная вероятность класса k для объекта i

**Почему именно эта функция?** Если модель уверена в правильном ответе (p ≈ 1), то log(p) ≈ 0, штраф мал. Если модель ошибается с высокой уверенностью (p ≈ 0 для истинного класса), то log(p) → -∞, штраф огромен. Это мотивирует модель быть уверенной только в правильных ответах.

#### StandardScaler (`model.py:10-13`)

```python
Pipeline([
    ("scaler", StandardScaler()),
    ("clf", LogisticRegression(**params)),
])
```

**Зачем?** Логистическая регрессия использует градиентный спуск. Если признаки имеют разный масштаб (например, `size_bytes` от 10 до 10⁹, а `digit_ratio` от 0 до 1), то градиент будет "дёргаться", и сходимость замедлится.

StandardScaler делает:
```
z = (x - μ) / σ
```

Где μ — среднее, σ — стандартное отклонение. После преобразования все признаки имеют среднее 0 и дисперсию 1.

**Важно:** Random Forest и Gradient Boosting **не требуют** масштабирования, потому что они основаны на пороговых правилах (сравнение `x_i > threshold`), а не на градиентном спуске.

#### Преимущества и недостатки LR

| Преимущества | Недостатки |
|---|---|
| Интерпретируемость: веса w показывают важность признаков | Линейная граница: не может разделить сложные зависимости |
| Быстрое обучение | Требует масштабирования |
| Хорошо калиброванные вероятности | Bias может быть высоким |
| Работает с малым числом признаков | |

### 4.2. Случайный лес (RandomForest)

#### Интуиция
«Толпа мудрее единицы.» Random Forest строит много «слабых» деревьев решений, каждое на своей случайной подвыборке данных и признаков, а потом усредняет их предсказания.

#### Как строится одно дерево решений

Дерево решений — это набор правил вида:
```
Если filename_digit_ratio > 0.3 → идём в левый потомок
Иначе → идём в правый потомок
```

На каждом шаге нужно выбрать: **какой признак** и **какой порог** дают наилучшее разделение классов.

**Критерий — Gini impurity:**
```
Gini = 1 - Σₖ (pₖ)²
```

Где pₖ — доля объектов класса k в узле.

**Пример:** в узле 10 файлов: 4 документа, 4 картинки, 2 архива.
```
Gini = 1 - (0.4² + 0.4² + 0.2²) = 1 - (0.16 + 0.16 + 0.04) = 0.64
```

Чем меньше Gini, тем чище узел. Идеальный узел (только один класс): Gini = 0.

На каждом разбиении мы ищем признак и порог, которые **максимально уменьшают Gini**:
```
ΔGini = Gini_parent - (n_left/n)·Gini_left - (n_right/n)·Gini_right
```

#### Ансамбль — Bagging

Random Forest строит B деревьев (n_estimators=100). Каждое дерево обучается на **bootstrap-выборке** — случайная выборка с возвращением, того же размера, что и оригинальная.

**Почему это работает?** Каждое дерево видит разные данные и разные признаки, поэтому они делают разные ошибки. Усреднение B слабых моделей даёт сильную:

```
ŷ = argmax Σ_b [T_b(x) = k]   # голосование большинством
```

Деревья также случайно выбирают признаки: на каждом разбиении рассматривается не все 48 признаков, а случайное подмножество размером `√48 ≈ 7` (по умолчанию). Это уменьшает корреляцию между деревьями.

#### Преимущества и недостатки RF

| Преимущества | Недостатки |
|---|---|
| Не требует масштабирования признаков | Большой размер модели (100 деревьев → много МБ) |
| Устойчив к переобучению | Медленнее LR на инференсе |
| Считает важность признаков (feature_importances_) | Менее интерпретируем, чем LR |
| Работает с пропущенными значениями | |

#### Feature Importance

У Random Forest есть встроенный механизм оценки важности признаков: считаем, на сколько каждое разбиение на признаке уменьшает Gini, и суммируем по всем деревьям. Чем больше суммарное уменьшение — тем важнее признак.

### 4.3. Градиентный бустинг (GradientBoosting)

#### Интуиция
Если Random Forest — «параллельный» ансамбль (деревья независимы), то Gradient Boosting — «последовательный». Каждое следующее дерево учится **исправлять ошибки предыдущих**.

#### Математика

Начинаем с константного предсказания:
```
F₀(x) = argmin_c Σ L(yᵢ, c)
```

Для многоклассовой классификации с кросс-энтропией начальное предсказание — log-odds каждого класса.

Затем для m = 1 до M (n_estimators) повторяем:

1. Считаем **псевдо-остатки** (отрицательный градиент loss-функции):
   ```
   rᵢₘ = -[∂L(yᵢ, F(xᵢ)) / ∂F(xᵢ)]
   ```

2. Обучаем дерево hₘ(x) на остатках rᵢₘ

3. Обновляем модель с шагом learning_rate:
   ```
   Fₘ(x) = Fₘ₋₁(x) + ν · hₘ(x)
   ```

**Ключевой параметр — learning_rate ν.** Маленький ν (0.01-0.1) = медленное обучение, но меньше риск переобучения. Большой ν (0.3-1.0) = быстрое обучение, но легко переобучиться.

#### Почему `max_depth=3`?

В проекте глубина деревьев ограничена 3:
```python
"gradient_boosting": {"n_estimators": 100, "learning_rate": 0.1, "max_depth": 3}
```

Глубина дерева — это сколько последовательных вопросов (разбиений) может сделать дерево. Глубина 3 → максимум 2³ = 8 листьев. Это «слабые» деревья, каждое из которых улавливает только простые взаимодействия признаков. Бустинг из слабых деревьев с ν < 1 — мощная регуляризация.

**Сравнение с RF:** в RF деревья глубокие (max_depth=None), каждое дерево сложное и может переобучиться, но ансамбль усредняет ошибки. В GB деревья мелкие, но каждое новое фокусируется на ошибках предыдущих.

#### Преимущества и недостатки GB

| Преимущества | Недостатки |
|---|---|
| Часто лучшее качество на практике | Чувствителен к шуму в данных |
| Работает с разными loss-функциями | Последовательное обучение (не распараллеливается) |
| Меньше склонен к переобучению при правильных параметрах | Больше гиперпараметров (n_estimators, lr, max_depth, subsample...) |
| Feature importance как у RF | |

## 5. Процесс обучения

### 5.1. Разбиение данных

В `train.py:27-40` реализовано трёхуровневое разбиение: train / val / test = 60/20/20.

```python
def train_test_val_split(X, y, test_size=0.2, val_size=0.2):
    # 1. Отделяем test целиком (20%)
    X_temp, X_test, y_temp, y_test = train_test_split(
        X, y, test_size=0.2, stratify=y)

    # 2. Из оставшихся 80% отделяем val (20% от 80% = 16% от общего)
    #    Итого: train=64%, val=16%, но в коде:
    #    val_relative = 0.2 / (1 - 0.2) = 0.25 → 25% от 80% = 20%
    val_relative = val_size / (1 - test_size)  # 0.2/0.8 = 0.25
    X_train, X_val, y_train, y_val = train_test_split(
        X_temp, y_temp, test_size=val_relative, stratify=y_temp)
```

Итог: train = 64%, val = 16%, test = 20%.

**Стратификация** (параметр `stratify=y`): сохраняет пропорции классов во всех выборках. Если в данных 60% документов, 20% картинок и 20% остального, то в train/val/test будет то же соотношение. Без стратификации может оказаться, что какой-то редкий класс не попал в train.

### 5.2. Обучение (`train.py:78-98`)

```python
for name in models_to_train:

    val_metrics = evaluate_model(model, X_val, y_val)    # оцениваем на val

    joblib.dump(model, f"{name}.pkl")  # сохраняем
```

**Зачем val и test?**

- **Test** — финальная объективная оценка. Модель никогда не видела test во время обучения.

## 6. Метрики оценки

### 6.1. Confusion Matrix (матрица ошибок)

Для 6 классов — матрица 6×6. Строки = истинный класс, столбцы = предсказанный. На диагонали — правильные ответы.

```
          pred: doc   img  arch  code  media  other
true: doc      [ 45    2     1     0     1      1 ]
      img      [  3   50     0     0     2      0 ]
      arch     [  0    0    40     0     0      0 ]
      code     [  1    0     0    48     0      1 ]
      media    [  2    1     0     0    42      0 ]
      other    [  1    0     1     1     2     40 ]
```

### 6.2. Precision, Recall, F1

**TP (True Positive)** — правильно предсказали класс
**FP (False Positive)** — ошибочно приписали класс
**FN (False Negative)** — пропустили объект класса

**Precision (точность):**
```
P = TP / (TP + FP)
```
Из всех объектов, которые модель назвала "documents", сколько действительно документы? Наказывает за ложные срабатывания.

**Recall (полнота):**
```
R = TP / (TP + FN)
```
Из всех настоящих документов, сколько модель нашла? Наказывает за пропуски.

**F1-score:**
```
F1 = 2 · P · R / (P + R)
```
Гармоническое среднее. Одновременно штрафует и за ложные срабатывания, и за пропуски.

**Macro-F1:** считаем F1 для каждого класса, усредняем. Каждый класс учитывается одинаково, независимо от его частоты. Хорошая метрика для несбалансированных данных.

**Weighted-F1:** считаем F1 для каждого класса, усредняем с весом = число объектов класса. Если класс "other" встречается в 2 раза чаще "code", его F1 весомее.

### 6.3. Accuracy

```
Accuracy = (TP + TN) / (TP + TN + FP + FN)
```

Доля правильных ответов. Простая, но не подходит при дисбалансе классов. Если 90% файлов — документы, модель всегда предсказывающая "documents" будет иметь accuracy 90% — но F1-macro будет ужасным.

## 8. Bias-Variance Tradeoff

Это фундаментальная концепция ML. Ошибка модели раскладывается:

```
Ошибка = Bias² + Variance + Неустранимая ошибка (noise)
```

**Bias (смещение):** ошибка из-за того, что модель слишком простая и не может уловить сложные зависимости в данных. Модель "недоучивается" (underfitting).

**Variance (разброс):** ошибка из-за того, что модель слишком чувствительна к малым изменениям в данных. Модель "переучивается" (overfitting) — запоминает шум вместо сигнала.

**Пример:**
- **Линейная регрессия** (и LR): высокий bias, низкая variance. Простая модель не может идеально разделить классы, но стабильна.
- **Одно глубокое дерево:** низкий bias, высокая variance. Идеально подгоняется под train, но на новых данных падает.
- **Random Forest:** средний bias, средняя variance. Bagging уменьшает variance без увеличения bias.
- **Gradient Boosting:** может быть и тем, и другим. Мелкие деревья, ν → bias высокий, variance низкая. Глубокие деревья, ν → наоборот.

**Как определить переобучение?**
- Train accuracy >> Val accuracy (разрыв > 5-10%)
- Смотрим на метрики в `train.py`: если val F1 намного ниже train — переобучение

## 9. Регуляризация

Регуляризация — способ борьбы с переобучением. Добавляем штраф к функции потерь:

### L2-регуляризация (Ridge)
```
L = loss + λ · ||w||²  = loss + λ · Σ wⱼ²
```

Штрафуем за большие веса. Ни один вес не обнуляется, но все становятся меньше.

### L1-регуляризация (Lasso)
```
L = loss + λ · ||w||₁  = loss + λ · Σ |wⱼ|
```

Штрафуем за сумму модулей весов. Многие веса обнуляются — модель автоматически отбирает признаки.

### В проекте

В LogisticRegression параметр **C** — обратная сила регуляризации:
```python
"logistic_regression": {"C": 1.0}
```

`C = 1/λ`. Чем меньше C, тем сильнее регуляризация. `C = 1.0` — умеренная L2-регуляризация.

В RF и GB регуляризация через:
- **n_estimators** — больше деревьев → меньше переобучение, но медленнее
- **max_depth** — глубина деревьев (в GB = 3)
- **learning_rate** — шаг бустинга (в GB = 0.1)

### 10.3. Энтропия — магия numpy (`features.py:86-92`)

```python
def compute_byte_entropy(content: bytes) -> float:
    # np.frombuffer: bytes → массив uint8
    # np.bincount: считает, сколько раз встречается каждый байт 0..255
    counts = np.bincount(np.frombuffer(content, dtype=np.uint8), minlength=256)

    # Нормируем → вероятности
    probs = counts / counts.sum()

    # H = -Σ p·log₂(p)
    ent = -np.sum(p * np.log2(p) for p in probs if p > 0)
    return float(ent)
```

**Пошагово на примере** текста "hello" (104, 101, 108, 108, 111):
1. `np.frombuffer(b"hello", dtype=np.uint8)` → array([104, 101, 108, 108, 111])
2. `np.bincount(..., minlength=256)` → array(256 элементов, все 0, кроме counts[104]=1, counts[101]=1, counts[108]=2, counts[111]=1)
3. `probs = counts / 5` → probs[104]=0.2, probs[101]=0.2, probs[108]=0.4, probs[111]=0.2
4. `ent = -(0.2·log₂(0.2) + 0.2·log₂(0.2) + 0.4·log₂(0.4) + 0.2·log₂(0.2))` ≈ 1.92

Для короткого текста энтропия низкая. Для случайных байт — высокая (до 8.0).

## 11. Возможные вопросы на экзамене

### Вопрос 1: «Почему энтропия Шеннона в признаках?»

**Ответ:** Энтропия Шеннона — это мера неопределённости/случайности данных. Для текстовых файлов энтропия низкая (~4), так как используются только буквы ASCII. Для сжатых архивов — высокая (~7.9), биты распределены почти равномерно. Для изображений — средняя (~6-7). Это позволяет модели различать типы содержимого, не открывая файл полностью. Математически: `H(X) = -Σ p(x)·log₂(p(x))`, где p(x) — частота байта со значением x.

### Вопрос 2: «Почему LogisticRegression в пайплайне со StandardScaler, а Random Forest — без?»

**Ответ:** LogisticRegression обучается градиентным спуском, где веса умножаются на признаки. Если один признак имеет масштаб 10⁹ (размер в байтах), а другой — 0-1 (one-hot), то градиент будет нестабильным. StandardScaler приводит все признаки к среднему 0 и дисперсии 1. Random Forest не использует градиентный спуск — он строит деревья с пороговыми правилами (x_i > threshold), которым масштаб не важен.

### Вопрос 3: «Зачем три модели, а не одна?»

**Ответ:** Каждая модель имеет разный bias-variance tradeoff. LogisticRegression — простая линейная модель (высокий bias, низкая variance), хороша как baseline и для интерпретации весов. Random Forest — ансамбль деревьев (средний bias, средняя variance), устойчив к переобучению. Gradient Boosting — последовательный ансамбль, часто даёт лучшее качество, но требует осторожной настройки. Сравнение трёх моделей на одних данных позволяет выбрать лучшую для конкретной задачи.

### Вопрос 4: «Какие признаки самые важные?»

**Ответ:** Судя по интуиции задачи: на первом месте — расширение файла (ext_cat_{...}), так как оно напрямую связано с классом. На втором — ключевые слова в имени (kw_{...}). Дальше — энтропия и размер. Random Forest может показать feature_importances_ количественно.

### Вопрос 5: «Как боретесь с переобучением?»

**Ответ:**
1. **Валидационная выборка** (val/test split) — контролируем, что метрики на val не сильно отстают от train
2. **Стратификация** — гарантируем, что все классы представлены во всех выборках
3. **L2-регуляризация** в LogisticRegression (параметр C)
4. **Ограничение глубины** в Gradient Boosting (max_depth=3)
5. **Ансамбль** в Random Forest (усреднение 100 деревьев уменьшает variance)
6. **Синтетические данные** — увеличиваем размер датасета (больше данных → меньше переобучение)

### Вопрос 6: «Расскажи про bias и variance на примере трёх моделей»

**Ответ:** Представим, что истинная зависимость — сложная нелинейная функция, а мы пытаемся её аппроксимировать.
- **LogisticRegression** — пытается провести прямую (гиперплоскость) через данные. Она «смещена» — никогда не сможет идеально разделить классы, даже если данных бесконечно много (высокий bias). Но если дать разные обучающие выборки, её ответ будет стабильным (низкая variance).
- **Random Forest** — каждое дерево может идеально разделить train, но разные выборки дадут разные деревья. Усреднение уменьшает variance, но bias остаётся небольшим (деревья могут уловить нелинейности).
- **Gradient Boosting** — последовательно исправляет ошибки. Если ν мал, то bias снижается медленно, но зато variance мала. Если ν велик — быстро подгоняется под данные, но может переобучиться (высокая variance).

### Вопрос 7: «Что такое кросс-энтропия и почему она используется?»

**Ответ:** Кросс-энтропия — это мера «расстояния» между истинным распределением y (one-hot) и предсказанным p̄:
```
H(y, p̄) = -Σ y_k · log(p̄_k)
```
Она обладает свойством: если модель уверена в правильном ответе (p ≈ 1), штраф ≈ 0. Если модель с высокой уверенностью ошибается (p ≈ 0 для истинного класса), штраф → ∞. Это мотивирует модель быть уверенной только в правильных ответах. Кроме того, кросс-энтропия — выпуклая функция, что гарантирует сходимость к глобальному минимуму для LR.

### Вопрос 8: «Почему выбираете модель по F1-macro, а не accuracy?»

**Ответ:** Accuracy может вводить в заблуждение при дисбалансе классов. Если в данных 80% документов, модель «всегда документ» получит accuracy 80%, но не сможет классифицировать ничего, кроме документов. F1-macro даёт равный вес каждому классу, независимо от его частоты. Если модель плохо классифицирует редкий класс (например, архивы), macro-F1 это покажет, хотя accuracy может быть высокой.

### Вопрос 9: «Что такое one-hot encoding и зачем он в признаках?»

**Ответ:** One-hot encoding превращает категориальную переменную (например, группу расширения: doc, img, arc, code...) в набор бинарных признаков. Для группы `code` получаем вектор `[0,0,0,1,0,0,0]` длины 7. Это нужно, потому что ML-модели работают с числами, и кодирование `doc=1, img=2, arc=3...` создало бы ложный порядок (мол, arc > img), которого нет.

### Вопрос 10: «Расскажи про стратификацию в train_test_split»

**Ответ:** Стратификация — это разбиение данных так, чтобы пропорции классов в train/val/test совпадали с исходными. Без стратификации может возникнуть ситуация: редкий класс из 5 объектов попал весь в test, и модель не училась на нём. Со стратификацией: если класс 10% данных, то и в train, и в val, и в test будет ~10% этого класса.
